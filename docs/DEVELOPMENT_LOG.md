# ITS 项目全周期开发与验证记录

本记录详细描述了项目从概念验证到最终优化交付的全过程。

## 阶段一：需求分析与知识库建设
- **目标**：解决联想技术支持文档的智能问答问题。
- **数据源**：抓取并清洗了约 1000 份 `.md` 格式的技术手册。
- **技术点**：
    - 选择了 `text-embedding-v3` 作为向量化模型。
    - 搭建了 `backend/knowledge` 微服务，实现向量库与关键词库的混合索引。
    - **验证**：通过 Playground 测试，确认在嵌入模型离线时，系统能自动退化至 Jieba 关键词检索。

## 阶段二：Agent 架构设计与意图调度
- **目标**：实现“技术咨询”与“周边服务”的自动分发。
- **演进**：
    - **V1**：单智能体结构，Prompt 过长导致地理位置识别频繁出错。
    - **V2**：引入 `Orchestrator`（编排者）模式，采用多智能体协作机制。
    - **优化**：为 `Orchestrator` 选用了响应更快的 `qwen-flash` 模型，提升调度效率。

## 阶段三：外部工具集成与性能瓶颈突破
- **地图引擎迁移**：
    - 最初使用高德 MCP，但发现 API 调用频率受限且稳定性不足。
    - 切换为**百度地图 REST API**，手动封装了地理编码、周边搜索和路网距离工具。
- **性能攻坚**：
    - 记录：初版查询附近维修站需 15 秒以上。
    - 改进：实现了路网距离的批量计算（Batch Route Matrix），响应耗时降至 5 秒内。

## 阶段四：功能修复与体验增强
- **SSE 修复记录**：解决了由于 `Raw Delta` 解析逻辑不兼容导致的咨询平台无回复问题。
- **会话加固**：在 Redis 中增加了 `session_meta` 结构，支持自动提取对话标题及会话类型的自动识别。
- **快捷键优化**：移除了与浏览器冲突的 `Ctrl+K` 逻辑，改为更符合习惯的交互方式。

## 阶段五：可观测性与评估系统建设
- **可观测性**：接入 LangSmith，完成了对所有 Agent 运行配置的追踪。
- **自动化测试**：
    - 编写了 `tests/integration/` 下的 API 集成测试。
    - 引入 **Ragas** 对 RAG 效果进行了基准测试（Benchmark），当前 Faithfulness 得分保持在 0.85 以上。

## 阶段六：服务网点能力重建与全链路质量建设（2026-08）
- **定位服务统一**：
    - 抽离 `location_service` 统一定位解析：会话缓存（GPS 24h/文本 2h/IP 30min 差异化 TTL）→ 前端坐标 → 文本地理编码 → IP 定位（仅公网）四级降级，全失败时 Agent 主动追问而非静默兜底。
    - 设计**多坐标系契约**：前端传 `wgs84:/gcj02:/bd09:` 前缀坐标，后端自动转换百度坐标系，兼容任意定位 SDK。
- **网点检索与核验重建**：
    - 三关键词（客户服务中心/授权服务站/维修）并行检索，POI 召回量从约 10 提升至 26。
    - **加权评分核验**：电话归一化 0.6 + 名称相似度 0.25 + 地址 Jaccard 0.15，命中官方库回填全字段；电话一致或名称相似且间距 < 150m 合并去重；输出 ✅/❓/⚠️ 分级展示。
    - 距离口径修正：路网距离优先（批量 Route Matrix）、直线距离兜底，均明确标注，消除 `detail_info.distance` 读取错误导致的 0 值污染排序。
- **数据工程**：
    - 幂等建库：`name_addr_hash` 唯一键 + 启动自动迁移 + `city` 来源字段。
    - 全国 76 城采集脚本：逐城入库、302 配额熔断、断点续传、`--cities`/`--dry-run` 参数化。
- **稳定性排障**（详见 INTERVIEW_QA.md Q14/Q15）：
    - MCP 兼容三层修复：自研 POST 客户端（`2024-11-05` 协议）→ 补 `use_structured_content` 属性（缺失导致每次调用 AttributeError 被 SDK 吞掉 → 模型重试至 Max turns）→ MCP 联网搜索**首次在模型链路真正跑通**（此前仅客户端直连验证）。
    - 模型幻觉调用：提示词不再提及未注入的工具名；MCP 就绪时自动摘除本地兜底工具（消除同名误选）。
    - 多轮模仿：`SimpleSession.get_items` 过滤历史中的工具调用条目，阻断 temperature=0 下调度者对子 Agent 工具调用的模仿（曾致 500）。
    - 依赖锁定：`passlib 1.7.4` 与 `bcrypt>=4.1` 不兼容，锁定 `bcrypt==4.0.1`。
- **质量建设**：
    - 新增 `backend/tests/`：44 项纯逻辑单测（评分/坐标/去重/追问链路）、工具冒烟测试、**16 项 API E2E**（健康/鉴权/会话/四类对话/流式/严格 RAG/故障对话回放/历史去重/清理）、联网搜索路由回归（免地图配额）。
    - E2E 工程要点：唯一 `session_id` 防历史模仿假失败；配额预算管理（单次运行消耗可预估）。

---

## 最终验证结果
- **功能性**：咨询平台与管理平台完全联动，支持流式对话、位置感知、会话管理；维修站查询支持官方授权核验与分级展示；联网搜索经 MCP 实时返回。
- **稳定性**：具备 60s 超时保护与异常全局捕获，支持 7 天分布式会话持久化；E2E 12/12、纯逻辑单测 44/44 全绿。
- **专业度**：项目结构已按照微服务标准精简，所有核心逻辑均有文档覆盖。
